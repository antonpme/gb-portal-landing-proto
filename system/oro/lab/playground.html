Playground layouts

Four ways to build the same block, so one of them can be chosen and the rest thrown away. A, B and C hold the axes and the specimen identical and change only the arrangement. D takes A's arrangement and changes the controls instead: its panel is rendered from a schema, and each axis gets the control its shape asks for. Nothing on this page is in the system yet, and no showcase wears any of it.

Window width right now: measuring. The specimen is the live button organism at that width.

Variant A

The panel and the stage

Axes in a narrow white panel on the left, stage on the right taking the rest. The panel is a list you read down; the stage is the only large surface in the block.

Markup
Variant B

The stage over a strip

Stage across the full width, axes under it in one strip. It puts the specimen first and the controls second, which is the opposite of the reading order the other two keep, and that is the thing to judge here.

Markup
Variant C

The console and the canvas

The axes are a console: one grey block on the left that reads as an instrument rather than as page text. The stage is framed and wears a head bar that names what is standing on it and holds the ground switch.

Markup
Variant D

The panel built by rule

Variant A again, so the layout is not what is being compared: the difference is that the panel is rendered from a schema and each axis gets the control its shape asks for. Two or three values are a segment, four or more are a Select, a boolean is a segment of two. Icon position is not drawn until there is an icon, and the two axes nobody sets first are under More.

Markup
Variant D, second component

The same panel, on a field

The same renderer and the same rules, given the field instead of the button, which is the point of a schema: a showcase describes its component and gets a panel. Label style is only drawn for the three looks that have one, so the phone, the one time code and the password never offer a choice that does not exist.
