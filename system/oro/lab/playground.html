Playground layouts

Five ways to build the same block, so one of them can be chosen and the rest thrown away. A, B and C hold the axes and the specimen identical and change only the arrangement. D takes A's arrangement and changes the controls instead: its panel is rendered from a schema, and each axis gets the control its shape asks for. E puts C's colours and frame around D's schema and gives every short set a row of buttons instead of a row of words. Nothing on this page is in the system yet, and no showcase wears any of it.

Window width right now: measuring. The specimen is the live button organism at that width.

Variant A

The panel and the stage

Axes in a narrow white panel on the left, stage on the right taking the rest. The panel is a list you read down; the stage is the only large surface in the block.

Markup
Variant B

The stage over a strip

Stage across the full width, axes under it in one strip. It puts the specimen first and the controls second, which is the opposite of the reading order the other two keep, and that is the thing to judge here.

Markup
Variant C

The console and the canvas

The axes are a console: one grey block on the left that reads as an instrument rather than as page text. The stage is framed and wears a head bar that names what is standing on it and holds the ground switch.

Markup
Variant D

The panel built by rule

Variant A again, so the layout is not what is being compared: the difference is that the panel is rendered from a schema and each axis gets the control its shape asks for. Short sets are a segment, five or more are a Select, a boolean is a segment of two. Icon position is not drawn until there is an icon, and the two axes nobody sets first are under More. Size moved off the Select on 29 August: four values is not a long list.

Markup
Variant D, second component

The same panel, on a field

The same renderer and the same rules, given the field instead of the button, which is the point of a schema: a showcase describes its component and gets a panel. Label style is only drawn for the three looks that have one, so the phone, the one time code and the password never offer a choice that does not exist.

Markup
Variant E

E · C colours, D logic, one control per axis type

C's console and framed stage, D's schema, and the control rule as it now stands: a short named set is a row of buttons with one pressed, a Select is for a long list, free text is a field. There is no Select in this panel at all: State has five values and still reads as buttons over two rows. Icon position, and the glyph under More, are not drawn until there is an icon.

Markup
Variant E, second component

The same panel, on a field

The same renderer given the field. Look has five values, so it is the one Select on the bench. State has six, and it is drawn twice on purpose, as a Select and as a row of buttons, both moving the same axis: the question of which reads better on a long set is answered by looking at them rather than by arguing. Type is only asked of the two looks that have a choice, and the error text only exists while the state is Error.
