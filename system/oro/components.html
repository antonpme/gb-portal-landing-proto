States

Nine variants across five states

Rows are a type crossed with a colour, columns are the five states, and every cell is a real button. Hover always darkens. That is a rule and not a preference: a button that lightens under the pointer reads as switched off, and it is the one thing about our buttons the live product has already corrected us on. Focus is a ring rather than a colour change, so it can sit on top of any other state without arguing with it, and it appears for the keyboard only.

Anatomy

What each ladder measures right now

The table is measured, not typed: four hidden buttons wearing the four sizes are read with getComputedStyle every time the window changes size, so what you see is what this browser is rendering at this moment. Resize the window and the table moves with the ladders, which is the only honest way to show a scale that depends on screen width.

A note on the proportion formula of 17 August, pad-y = 0.24H and pad-x = 0.5H with the gap equal to pad-y. It still describes the small end well: 36 gives 8.6, which rounds to the live 8. Above that, live and the formula part company. The live form submit and the live product CTA both hold pad-y at 8 and run their gaps two or three times wider than that. Where live has measured a number, live wins, and the formula is the tie breaker for the sizes live has never shown, which is why every number of the new M ladder is marked declared.

Usage

Which cell, and when

Blue is state, black is furniture. That split is not decoration: it is the rule that keeps the accent meaning something, and it decides the colour before anything else does.

Reach forWhenNot when
Filled primaryThe single action the screen is asking for: Place order, Continue, Book a meetingNever twice in one view. Two blue buttons side by side means neither of them is the answer
Filled secondaryFurniture that still has to carry weight, standing where no blue action competes with itBeside a filled primary. Use an outline there instead
Outline primaryA second action of the same rank, beside a filled oneAlone on a screen. If it is the only action, it is the primary and should be filled

Code

The base class plus three words. Filled, primary and L are the defaults, so a bare gb-btn is already the button most screens want.

<!-- the default: filled, primary, L -->
<button class="gb-btn" type="button">
  <span class="gb-btn__label">Book a meeting</span>
</button>

<!-- a header button: small, outlined, black -->
<a class="gb-btn gb-btn--s gb-btn--outline gb-btn--secondary" href="#">
  <span class="gb-btn__label">My portal</span>
</a>

<!-- a form submit: full width, glyph at the padding edge -->
<button class="gb-btn gb-btn--l gb-btn--block" type="submit">
  <span class="gb-btn__icon"><svg>...</svg></span>
  <span class="gb-btn__label">Continue</span>
</button>

Which side the glyph stands on is DOM order and nothing else. There is no left modifier and no right modifier, because the row already answers that question and a second way to say it would be a second thing to keep in step. Two glyphs is two spans. The one exception is --block, where the glyph is pinned to the padding edge and DOM order stops mattering: a full width button has one glyph and it belongs at the far edge.

Migration

What each old class became

Ton approved the migration on 26 August. Four local button ladders lived across the prototypes, each written for the screen it was needed on, and all four are gone. Nothing was left behind as an alias: an alias is a second name for the same thing, and a second name is the drift this organism exists to end.

What the consumers kept is layout only: where the button stands, how wide its row is, what margin sits over it. The checkout drawers were migrated with the rest; their steppers, pagination and text links were not, because those are controls and not buttons of this organism. One button on that page is still outside the system, the red Overwrite all, because the organism has no danger colour yet. That is a decision for Ton, not a cleanup.

States

Six states, and one the system has not decided

The live field has no focus ring. Focus does exactly one thing on the product: it fades the placeholder out and leaves the underline where it was. Hover is the only step that moves the line, and it moves it to blue. That is not an omission on our side, it is what the instrument read, and the showcase shows it rather than improving on it quietly.
